# dsh-lumen · 流转壁纸

> DeepSeek Harness（DSH）的壁纸插件：1 套**纯程序化生成**的晨雾壁纸 + 4 张随包插画，加上本地图片 / 图片地址两类自定义（本地图片支持**多选与拖拽批量导入**，并在导入时**实测照片亮度**来驱动可读性下限），再配一个真正意义上的**轮播调度器** —— 按间隔、整点、每日或每次会话自动换图，带交叉淡入。
>
> 生成式壁纸零图片素材、零运行时依赖，**完全离线**算出；四张插画随包内置（约 1.1 MB），由宿主本机路由送出，不出网。开屏另配一段随包内置的短片，装好即默认启用。

`dsh-lumen` 的目标不是"换一张好看的图"，而是回答两个问题：**现在显示什么**，以及 **下一次什么时候变、变成什么**。

## 它和常见的换肤插件有什么不同

现有的 DSH 壁纸 / 换肤插件把壁纸当成"皮肤系统的一部分"：壁纸是贴上去的一层材质，主题才是主体。`dsh-lumen` 走的是另一条路，有三处根本性的取舍：

| | 常见做法 | dsh-lumen |
| --- | --- | --- |
| **壁纸从哪来** | 打包图片素材，或让用户自己传 | 两套**参数化配方**用 CSS 渐变算出来，可选的内置集不随体积增长；另外四张插画随包内置 |
| **什么时候换** | 装上就一直是一张 | **调度器**：4 种触发方式 × 3 种顺序策略，落在可预测的钟点上 |
| **文字还看得清吗** | 交给用户调透明度 | 洗色层（wash）透明度对着 **WCAG AA 对比度求解**，只允许比用户设的更不透明 |

一句话概括：这是一个**壁纸调度器**，壁纸的生成方式只是它的素材来源之一。

## 功能一览

**壁纸来源**

- **2 套内置配方 + 4 张随包插画** —— 配方由参数实时生成，无图片素材；插画是固定的四张图，亮度在文件上实测
- **本地图片** —— **可多选，也可直接把文件拖到那一行**；自动等比缩放并压缩后保存（长边最多 2560px），原图不上传
- **图片地址** —— 仅接受 `http` / `https`
- **渐变** —— 双色标线性渐变，起止色 + 角度

**轮播调度器**

- 4 种触发方式：`按间隔` / `整点` / `每日` / `每次会话`
- 3 种顺序策略：`顺序` / `洗牌` / `随机`
- 播放列表最多 24 条，交叉淡入 0–4000ms（设 0 即瞬时切换）
- 显示"下一次更换"的倒计时与后续 5 个触发时刻
- 可随时暂停 / 继续；补上错过的轮次（有损追赶，见下文）

**外观调校**

- 洗色层透明度 0.2–0.98、模糊 0–60px
- 填充方式：`cover` / `contain` / `blur`
- **位置控制**：3×3 九宫格，把主体挪离左侧边栏
- 三轴微调：色相旋转（±180°）、柔度、颗粒
- 自动弱化：画面越"花"越自动抬升透明度
- 可读性下限：见下节；本地图片按**实测亮度**求解，而非常数

**开屏**

- **装好就有** —— 包内自带一段 5 秒短片（`media/splash.mp4`），`splash.source` 缺省即 `builtin`。想用自己的素材、想切回内置、想彻底关掉，各是一个按钮，不需要改配置
- **一个素材，两处去处** —— 选一个文件，然后决定它是当壁纸、当开屏，还是**两个都要**。同一个文件要两处用，不该选两次
- **图片开屏走纯 CSS** —— 注入的那段样式表由服务端和文档一起送达，所以它在**第一帧**就上色：早于任何客户端模块存在，也就无从"慢"或"失败"
- **视频开屏走浏览器半边** —— 全屏层 + 自动播放（静音：不静音的话浏览器一律拒绝自动播放，那就没有开屏了），拿到第一帧就放行界面，播完或点击/按键跳过即撤层
- **四个出口全部有界** —— 第一帧 8 秒、总寿命 120 秒、解码失败立即、用户跳过立即。**卡在中途的片子不发任何事件**，所以总寿命这条时限是单独留着的，不能被"已经开始播了"顶掉
- **两层时限各管各的** —— 遮罩的兜底（10 秒 / 延长后 30 秒）管的是遮罩，层的时限管的是层；图片路径根本不挂层
- **只存文件名** —— 上传的媒体字节写在 `$DSH_HOME/lumen-media/`，状态里只有宿主自己生成的名字，服务哪个文件由白名单形状拼出来；内置那份一个字节都不复制，直接从包内读（见 [`SPLASH-SPEC.md`](SPLASH-SPEC.md) §九）

**消息栏**

- **两笔装饰，一个开关** —— 输入框四边一圈 2.5px 的渐变蓝环（静止 75%，hover / 聚焦全亮），左边挂一只鲸鱼娘；点她收成一条尾巴，再点回来，聚焦时她往外探 4px
- **关掉就是没有** —— 关掉之后两个伪元素是 `content:none`，不是隐藏：环和鲸鱼娘根本不生成，也接不到点击；输入框与 DSH 原样一致
- **不碰宿主的布局** —— 环用 `mask-composite` 画在卡片自己的 padding box 里，不挤文字、也不吃 28px 圆角；聚焦的 `box-shadow` 是**换掉**而不是追加，因为宿主那套是一次 token 查询

**工程细节**

- 中英双语，两套字典各 **170** 条键、完全对称（没有只在一边存在的键）
- 持久化跨 DSH 重启生效（Host 侧状态文件 + `localStorage` 快速种子）
- 诊断快照挂在 `window.__DSH_LUMEN__`，可脚本读取
- 插件入口**从不抛异常** —— 最坏情况是"壁纸不出现 + 控制台一行日志"，不会让 DSH 起不来

## 6 套内置壁纸

前两套是**参数化配方**（由 CSS 渐变实时算出），后四套是**随包插画**（WebP 存在 `media/wallpapers/`，由宿主经 `/lumen/wallpaper` 送出）。`complexity` 是"画面有多花"的估计值（0–1），驱动自动弱化；插画的亮度是在文件上实测的，同样喂给可读性下限。

| ID | 名称 | 中文名 | 类型 | 取向 | complexity |
| --- | --- | --- | --- | --- | --- |
| `mist` | Mist | 晨雾 | 生成式 | 浅 | 0.20 |
| `whale-point-half` | Night Tide | 夜潮 | 插画 | 深 | 0.55 |
| `whale-starlit` | Starlit | 星海 | 插画 | 深 | 0.50 |
| `whale-sunset` | Dusk | 黄昏 | 插画（首次安装的默认） | 深 | 0.60 |
| `whale-point-full` | Deep Blue | 深蓝 | 插画 | 深 | 0.55 |

配方带一个 **seed**：同一个配方换一个种子就是同一风格的另一种构图（面板上的「摇一摇」，也可以复制种子分享给他人）。配方本身带深浅取向，但在另一套主题下同样能渲染。插画是一张固定的图，换种子不会变，所以那四张不显示「摇一摇」。

旧版本退役的几套（`aurora` 极光、`starfield` 星野、`dune` 沙丘、`drift` 弥散）会按意图就地改写：极光 → 晨雾、星野 → 星海、沙丘 → 晨雾、弥散 → 晨雾。

## 轮播调度器

这是本插件真正花力气的地方，也是和"贴一张图"的插件最本质的区别。

### 四种触发方式对应四种不同的"时间"

- **按间隔** —— 每 N 分钟（5–43200）。关键在于**锚定网格**：以启用轮播的那一刻为锚，之后严格踩在锚点上，而不是"距上次变更 N 分钟后"。后者听起来等价，但每次刷新页面都把计时器重置——一个经常刷新的用户会永远等不到第一次更换，而且会离钟面越来越远。
- **整点** —— 在每小时的第 N 分钟触发（可多选，如 :00 和 :30）。选这个的人希望换图落在一个自己能预判、能安排的时间上。
- **每日** —— 每天某个本地墙钟时刻（`HH:MM`），对应"每天早上换一张"。
- **每次会话** —— 每次重新看向应用时更换。这个模式**由可见性驱动，与钟表无关**，因为对"每次会话"来说钟表本来就不重要。

### 三种顺序策略

- **顺序** —— 按播放列表依次走。
- **洗牌** —— 用 Fisher–Yates 洗出一轮队列，**走完一轮之前不重复**（不是"每次随机抽一张"，那会出现连续两次同一张）。
- **随机** —— 每步独立随机，由单调递增的 `orderStep` 派生随机流，因此可复现、可测试。

改顺序策略会让 `orderRevision` 自增，从而丢弃上一轮的洗牌队列；否则队列是用旧列表长度算的，会指向不存在的下标。

### 有损追赶（deliberately lossy catch-up）

笔记本合盖睡过五个触发点，回来后**只换一次**，不是连补五次。补播会在用户眼前闪五张图、烧 CPU 去追一个只有最后一次才有意义的中间状态。这个取舍集中在 `planResume` 一个函数里。

### 纯函数实现

调度部分全部是 `(schedule, now) -> number` 的纯函数，浏览器半边只负责持有**一个**定时器。这样做的理由很实际：调度器的难点全在边界情况——睡过三个触发点、设备时钟被往回拨、夏令时跳变、洗牌模式下只有两张图的列表——而这些情况**没有一个能通过 `setInterval` 诚实地测出来**。写成纯函数，它们就是普通的单元测试。

## 可读性下限

壁纸可以以任何主题 token 都拦不住的方式毁掉文字对比度：画布被洗成半透明，压在一张任意图片上。所以：

1. 洗色层的 alpha 会对着 **WCAG 2.1 AA（4.5:1）** 求解；
2. 实际生效的 alpha 取 **"用户设定值"与"求解出的最小值"中较大的那个**；
3. 面板**把差异显示出来**，而不是偷偷改掉——一个滑块显示 30%、实际渲染 62% 而不吭声，正是这个项目刻意避免的谎。

求解不是简单套公式。关键在于必须区分**线性光域**和**伽马编码域**的量：对比度公式里的相对亮度是线性域的，而 CSS 的 `rgba()` 的 alpha 混合发生在伽马编码域，混用两者会在中间调上偏掉一大截。`color.cjs` 里的 `alphaForContrast` 的做法是：先把壁纸归约成一个**相对亮度相同的中性灰**（亮度估计本身是线性域加权平均，所以它在通道空间的等效平坦色就是它的平方根），在通道空间里做 alpha 合成，再对 alpha 二分——12 次迭代收敛到 0.1%，且结果**向上取整**（它是个安全下限，向下舍入会交出一个达不到目标的 alpha）。

图片的"有多花"也是估计出来的，而且**故意偏高估**：`estimateImageLuminance` 自下而上按**覆盖面积**加权合成，而不是数色标个数——一层覆盖 80% 画面的亮色，比八层各覆盖 5% 的亮色危险得多。

### 弱化文字：遮罩救不了的那一半

上面解的只有**正文色**。副文本是另一种问题，不是同一问题的弱化版：

| token | 用途 | 浅色主题 | 对纯白 |
| --- | --- | --- | --- |
| `--dsw-alias-label-secondary` | 次级文字 | `#61666b` | 5.80:1 |
| `--dsw-alias-label-tertiary` | 时间戳、用量、图标、代码块语言名 | `#81858c` | **3.71:1** |

tertiary 对纯白只有 3.71:1 —— 主题**故意**让它低于 AA 正文阈值，因为它承载的是可以扫一眼的元信息。所以把遮罩加到 1.0 也只能逼近 3.71，永远到不了 4.5，代价却是照片被压成一块板；而用户把「壁纸可见度」拉到 0.45、壁纸又偏亮时，那排图标和时间戳会掉到 **2.3:1** 左右，糊在照片里。

唯一还能动的杠杆是颜色本身。`labelForContrast` 在 Oklab 里把颜色朝"背离背景"的方向混合，二分求出刚好达标的最小混合量，规矩有四条：

- **方向由标签自身的极性决定**，不看 `scheme`：标签比背景暗就加深、比背景亮就提亮。主题标记写错也送不到反方向。
- **目标各是各的**：secondary 4.5，tertiary **3.0**（WCAG AA 对大字/非文本的阈值，正是 11–13px 元信息对着的那根线）。
- **有预算**：相对亮度最多移动 **0.10**。够不到目标就花完预算为止 —— 弱化层级是主题设计的一部分，抹平它是另一个缺陷。
- **够不到就不动**：连纯黑/纯白都达不到目标时（例如 mid-grey 背景上要求 4.5）返回 `null`，不重绘一个假装达标的颜色。

结果吸附到 5/255 网格、且只朝背离背景的方向吸：拖动滑杆时文字不会跟着一像素一像素地闪，而吸附方向保证值只会更远、不会更近。发布与撤销都跟遮罩同批（同一次 `overrideTokens`、同一个 disposer），只在可读性下限开着时生效；宿主没有这两条 token 时什么都不做。

### 本地图片：把猜测换成实测

内置配方和渐变是插件自己算出来的，亮度可以精确推导；随包插画在构建期量好写在配方上；**图片地址**不行——渲染路径是同步的，没有像素可看，而且跨域图片画进 canvas 会污染画布、`getImageData` 直接抛错。所以远程图片只能沿用那个**故意偏亮**的中性常数。

本地图片则不必猜：`prepareImage` 在导入那一刻手里已经握着解码后的位图，把它画进一张 64×64 的小画布读一遍像素，只多一次绘制，代价可以忽略。这个值随条目一起持久化（在宿主文件里与图片负载分开存放，因此即使图片字节被清理掉，亮度仍在），之后可读性下限就针对**这张真实的照片**求解。

读数取**上四分位**而不是平均值，因为平均值回答的是"这张图平均多亮"，而这是错的问题——文字压在画面上的**某一块**，要紧的是"亮到足以威胁对比度的那部分有多亮"。半黑半白的图平均亮度是 0.5，按 0.5 求解洗色，白的那一半照样读不了；上四分位在这里给 1.0。平坦的画面上分位会塌回平均值附近，所以不会白白多洗一层。全透明的像素直接跳过——抠图 PNG 的空白区域不属于画面，当成黑色会把估计拖垮。

读不出来时返回 `null` 而不是 `0`：`null` 是"没有测量"，引擎按回退处理；而 `0` 是纯黑，恰恰是唯一会让可读性下限彻底失效的值，把两者混起来会静默关掉保护。

## 安装

前置：DSH Desktop 或 DSH Web，Node ≥ 18。

安装、更新、卸载、以及 `--profile desktop` 会被 CLI 拒绝这件事的完整说明，见 **[`INSTALL.md`](INSTALL.md)**。最短路径是**在 DSH 的插件安装入口填仓库地址**——包根即仓库根，GitHub 地址可以直接装；插件还没发布到 npm，填包名会被当成 npm 包去查，报「未找到相关插件」：

```text
https://github.com/lhr040306/dsh-lumen
```

CLI 等价写法：

```sh
dsh plugin --profile web add github:lhr040306/dsh-lumen
```

（从本地目录安装就把来源换成仓库根目录的绝对路径。）

装完 **重启 DSH**，然后打开 **设置 → 壁纸**。若想先看效果再决定要不要装，直接跑[浏览器可交互预览](#浏览器可交互预览)。

## 使用

重启 DSH 后，设置面板左侧会多出一项 **「壁纸 / Wallpaper」**（`id: lumen`，排序 30）。面板自上而下是**四段**：壁纸、开屏、消息栏、状态。

| 段 | 分组 | 内容 |
| --- | --- | --- |
| 壁纸 | 当前壁纸 · 内置壁纸 · 自定义 · 更多设置 | 预览 + 摇一摇换种子 + 复制种子 + 加入播放列表；内置 1 个配方（晨雾）与 4 张插画（缩略图就是那张图）；本地图片（多选 / 拖拽）或图片地址；**折叠着**的「更多设置」里是轮播调度与外观 |
| 开屏 | 开屏 | 选一个文件 → 设为壁纸 / 设为开屏 / 全部；另有两个按钮：切回内置、关闭开屏。状态行由宿主回答，写清当前用的是内置还是自己的素材、多大 |
| 消息栏 | 消息栏 | 只有一个开关：输入框的 2.5px 蓝环与左边那只鲸鱼娘。关掉之后输入框与 DSH 原样一致 |
| 状态 | 状态 | 持久化健康、宿主通道是否可用、当前 DOM 与动效状态、诊断快照 |

**为什么轮播与外观是折叠的，壁纸那一段却始终展开。** 前两者是被改一次就不再进的设置，常年占着版面只会把「现在显示什么」挤到需要滚动才能看见；壁纸那一段回答的正好是这个问题，所以它不折叠。

「开屏」这一组**整块是条件渲染的**：`createPanel` 的 `splash` 依赖是可选的，宿主没注册开屏通道时这一组连标题都不出现，而不是出现一堆按不动的按钮。同样地，「设为壁纸 / 设为开屏 / 全部」三个按钮里，**视频只会看到一个**——这个插件里没有任何东西能把视频变成壁纸，而引擎的条目类型本来就是图片、渐变、URL 三种；把不可能的选项删掉，比事后解释它们为什么不行更诚实。

「全部」是**一次手势写两处**，所以它会如实报告一半成功的情况：壁纸上去了、开屏没上去（或反过来）时，那句话说的是做到的哪一半，而不是笼统的"已设置"。同一张图两处都要，是这里最常见的用法。

面板是**原地同步**而不是重建 DOM 的：每个控件保留句柄、`sync()` 推入当前状态。每次改动都重建的话写起来更简单，但会在拖动中途把指针下的节点换掉，让每个滑块都拖不动。只有真正呈列表形态的部分（配方卡片、播放列表、后续触发时刻）才重渲染，且仅在其内容变化时。重绘通过 `requestAnimationFrame` 合并——否则拖动透明度滑块每个像素像素都会重算一次配方和几千字符的 CSS 字符串。

## 持久化：为什么状态不会丢

DSH Desktop 每次启动都把 Web 服务绑到**系统随机分配的端口**上，因此页面 origin 每次都变。`localStorage` 是按 origin 隔离的，纯前端插件于是会在每次重开应用时"忘记"用户的壁纸——数据其实还在浏览器的 leveldb 里，只是被记在旧端口名下。

所以这里有两层：

- **权威副本**在宿主侧，落在 `$DSH_HOME/lumen.json`（默认 `~/.dsh/lumen.json`），经一条受围栏保护的 `/lumen/api` 路由读写，原子写（临时文件 + rename）。
- **`localStorage` 只充当种子**。它是同步的，所以刷新后第一帧画出来就已经是正确的壁纸，而不是先闪一下默认值再等 HTTP 往返。宿主答复返回后替换掉这个种子。两层共用同一份扁平序列化格式，避免两者各自漂移。

写入**携带意图而非整份文档**。宿主 API 是合并语义：缺席的键保持原值，显式 `null` 删除。因此插件只推送用户（或轮播引擎）真正改动的字段，并为消失的负载键推 `null` —— 一个曾被写入、现在已不存在的键必须删除，否则移除一条播放列表项会把它的图片字节永远留在磁盘上。推整份文档会更简单但更错：两个 DSH 窗口共享同一个 `$DSH_HOME/lumen.json`，只改了壁纸的那个窗口会把另一个窗口的洗色、微调和调度一起回滚掉。

**存储也是分层的。** 偏好在一个小 JSON 文档里，图片各自占一个键（宿主文件里是 `blob:<id>`，浏览器种子里是 `dsh-lumen:blob:<id>`）。这样一张塞不进去的图只会让它自己失败——播放列表、调度和洗色都不受影响。把包括数兆字节 data URL 在内的所有偏好放进同一张扁平表也能用，但让整份文档暴露在单个超大值的风险下：一张 6MB 的照片足以把存储配额顶爆，顺手带走用户的其他设置。

## 浏览器可交互预览

不想先装、想直接看效果时用这个：

**会启动一个本地服务**（`127.0.0.1:4173`，端口被占则向后顺延至多 12 个）：

```sh
npm run preview
```

然后打开终端里打印的 `http://127.0.0.1:4173/preview/`。

预览页左侧是一个用 `--dsw-*` token 画的 DSH 外壳仿件（侧栏、消息流、输入框），右侧是预览工具条。这里有四个刻意的设计：

1. **跑的是要发布的那个包**，不是效果图。预览加载真实的 `lib/client.js`，通过一个替身实现 `window.__ModuleLoader__`、`react` 种子，以及带 `theme` / `slots` / `locale` 的 ctx。右侧显示的设置面板就是面板本身，不是仿件。
2. **宿主半边也是真身挂上去的，预览服务器里没有第二份镜像。** `scripts/serve.cjs` 直接 `import()` `lib/index.js` 并调它的 `apply()`，拿到的是**它自己注册的路由**、它自己的状态文件、它自己的围栏和合并逻辑。早先那版服务器把这套东西复刻了一遍，结果是同一个协议有两个实现，改一边另一边不会报错——现在"预览能跑通"和"宿主能跑通"是同一件事。代价是服务器必须先把它要用的 `DSH_HOME` 钉在仓库内（`preview/.state/`），再加载宿主模块。
3. **所有读数都是算出来的，不是复述常量。**「覆盖了 2 个 token」这一行是把引擎的 `rawTokens()` 和 `visibleTokens()` 做差得到的；如果哪天覆盖面变了，这一行会跟着变，不会继续撒谎。
4. **可以拨钟。** 调度器最难测的是时间，而真实世界的时间又等不起。预览里有一排 `+15 分 / +1 小时 / +1 天 / +7 天` 按钮，会**真的平移 `Date.now()`**，然后走一遍和真实时钟跳变完全相同的代码路径。

关于拨钟有一个容易做错的地方，值得记下来：一个恒定偏移只是同一条时间轴的重新标注，所以**只有"现在"的来源需要移动**。`new Date(ts)`、`new Date(y, m, d, ...)` 和所有 getter 都必须原样不动，否则 `nextTriggerAt - Date.now()` 会因偏移量而整体错位。预览的时钟垫片只改 `Date.now()` 和无参 `new Date()`，测试也断言了这个后果（平移后算出的延迟仍落在一个周期内），而不是断言实现方式。

预览自己的状态文件在 `preview/.state/lumen.json`，和真实插件用的 `$DSH_HOME/lumen.json` **是两回事**，预览永远不会碰后者。预览服务只监听回环地址，只该文件可写。

### 想单独看开屏，打开 `preview/boot.html`

主预览页（`preview/index.html`）是给面板用的，它的 `<html>` 上**没有** `data-dsh-lumen-shell-document`，所以预览服务器**永远不往它里面注入遮罩和守卫**——否则每刷一次预览都要等一次开屏。

要看开屏就走 `http://127.0.0.1:4173/preview/boot.html`：它是外壳 `index.html` 的**替身**，带着那个标记，因此会被真正注入那两行。它的 `#root` 里放着一个 `[data-dsh-boot]`，`preview/boot.js` 用**两帧**把它换成 app 树——两帧不是一帧，是因为 `requestAnimationFrame` 的回调跑在它所属那次绘**之前**，在第一帧回调里就换掉的话，内核一次都没上过屏，而真实交接是会上屏的。开屏的释放时机就卡在这个信号上。

> `boot.html` 里那些中文文案（"外壳已接管"等）是**替身页面自己的**，不是插件文案——这个页面是工具，不随包发布。

## 隐私与安全

- **插件自身不发任何网络请求。** 内置壁纸是本地算出来的。`图片地址` 那一类是你自己给的 URL，由浏览器直接加载；插件不代理、不上报、不探测可达性。
- **壁纸不读磁盘。** 本地图片走浏览器 `File` API 读入（点选和拖拽走的是同一条路径，只是拿到 `File` 的方式不同），缩放压缩后以 data URL 存在本地存储，原图不会被复制到别处。拖拽处理器只读 `dataTransfer.files`，不碰文件系统路径。
- **开屏会写自己的媒体目录。** 开屏的时长和体积比壁纸大两三个数量级（壁纸是几百字节的渐变，20 秒视频是 2 MB），字节不适合放进状态文件。上传的媒体由宿主写入 `$DSH_HOME/lumen-media/`，**文件名由宿主生成**，状态里只留这个文件名——既不是路径，也不是字节。这样"服务哪个文件"由一段白名单形状拼出来，而不是由请求里的字符串拼出来。替换或「清除」都会把旧文件删掉。**内置那份不写盘**：它在包内，宿主直接读，切回内置也不复制一份过来——只是把状态里的来源标记改成 `builtin`，然后把用户那份文件删掉。
- **开屏视频不会出网。** 视频开屏同样是本地文件：选完先经导入管道把字节交给宿主，之后播放的是 `/lumen/splash/media` 这条本机路由。播放中的遮罩层挂在 `document.body` 上、用 `z-index: 2147483647`，在界面可用之前就已经被移除——它不常驻、不参与后续层叠。
- **开屏只在文档生成时决定。** 遮罩是服务端注入进 `index.html` 的两行（一个 `<style>`、一个 `<script>`），所以刚设好的开屏**要重新加载才看得到**；界面里那句话是真的，不是敷衍。关掉开屏的用户（`splash.source = "off"`），这两行一次都不会出现。
- **宿主路由是围栏，不是鉴权。** `/lumen/api` 与 `/lumen/splash` 过同样三道关：①插件自己的校验器——要求回环地址（或显式配置的可信 authority）的 `Host`，外加同源浏览器标记，这是 DNS rebinding / 跨站防御；②宿主提供的 `connection.requestRejection`，它补上浏览器会话鉴权（401）这一层，且**它抛异常时按拒绝处理**；③该服务缺失时退回①，并在加载期打一条告警。说明白在这里，免得被误当成访问控制。
- **重名也不冲突。** 所有 DOM 节点带 `data-dsh-lumen` 标记，样式表 id 为 `dsh-lumen-style`，存储键前缀 `dsh-lumen:`。

## 兼容性

- DSH Desktop 0.2.0-rc.2、Node 24.21.0 上实测通过
- `engines.node >= 18`；运行时不依赖任何第三方包（`require("react")` 走宿主模块表，取不到时只跳过设置面板，壁纸照常工作）
- peer 范围覆盖 `@deepseek-ai/dsh-client-*` `>=0.1.0-rc.6 <0.3.0-0`

已知边界：

- `contain` 填充在极端宽高比下会露出画布底色，这是该模式的预期行为，不是 bug。
- **位置控制只对"没铺满视口"的图片可见**。`cover` / `blur` 下图片按视口比例填满，九宫格会照常写入 `background-position` 但不产生视觉变化——要挪动主体，先用 `contain`。为了不让这条规则变成"有个开关时灵时不灵"，它对所有模式都无条件生效，而不是加一个只在 `contain` 下出现的分支。
- `每次会话` 模式由可见性驱动，因此在后台标签页里不会触发。
- 设置面板需要宿主的 `slots` 服务；缺失时壁纸仍生效，只是没有面板，控制台会留一行日志。
- **开屏要重新加载才会出现。** 遮罩是在**文档生成时**注入进 `index.html` 的，所以刚设好的开屏不会出现在你正看着的这一页上；面板里那句话就是这个意思。同一条规则的反面是：它不需要任何客户端代码就能在第一帧上色，图片开屏尤其如此。
- **开屏需要宿主注册 `/lumen/splash` 通道。** 宿主没注册时，面板里的「开屏」整组连标题都不渲染，而不是给你一个按不动的按钮。
- **视频开屏静音播放。** 不静音的话所有浏览器都会拒绝自动播放，而放不出来的开屏不叫开屏。要声音请自己配，那不属于本插件的范围。
- **内置开屏默认是开的。** 装好重启就能看见它，不需要任何设置；不想要就在开屏那一组点「关闭开屏」，之后这插件对文档零注入。这是刻意的默认值，不是漏配。
